## 可独立借鉴的文件

以下均位于 `fairy-visual/dsh-fairy-visual/src/client/`：

| 文件 | 内容 |
| --- | --- |
| `mascot-geometry.js` | 眼睛、瞳孔、高光与三种光晕的几何参数及验证 |
| `mascot-eye-svg.js` | 主眼 SVG：蓝色圆盘、四角眼睑、白色眼白、分层虹膜、右下高光 |
| `mascot-effects-svg.js` | 独立外部扫描线光场、扩散光圈 |
| `mascot-style.js` | 色彩、分层、CSS 动画、亮暗主题、低功耗样式 |
| `mascot-motion-clock.js` | 单一单调时钟、相位连续的变速与暂停/恢复 |
| `mascot-runtime.js` | 浏览器 RAF 驱动的分层呼吸，以及故障/状态调度；只宜提炼运动公式 |
| `mascot-assets.js` | 前述静态资源的明确聚合入口 |

不是播放一张现成 GIF，而是浏览器 SVG + CSS + requestAnimationFrame 的程序动画。
这些视觉数据可适配 Pi 的透明 PNG 图片层，但 DOM/CSS/浏览器调度不能原样搬到终端。

## 形象与白色光晕

参考实现 viewBox 为 160×160，中心 (80,80)：

- 蓝色外圆半径 68，白色描边宽 1.2；最外部软光晕半径 79。
- 白色眼白半径 48、软光晕半径 56，额外细接触边用于消除子像素接缝。
- 右下圆形高光中心 (98,100.5)、半径 11，高光软晕半径 18。
- 光晕采用多 stop 径向渐变形成平滑 alpha 衰减，不靠矩形背板或一圈硬描边。
- 除紧贴圆盘的软晕之外，还有独立的大范围扫描线光场与扩散脉冲；三者不能混为一谈。
- 上游浅色主题会将最外光场换成深色，但眼白与高光软晕仍是白色。

用户明确要求原始白色光晕。后续应保留白/淡蓝的主光晕；浅色终端用额外细暗边
提高识别度，不应简单把所有白色发光改成黑圈。必须给软晕留出真实透明画布余量，
避免它被 PNG 边界截成方框；也不能为了容纳超大光场而无意缩小眼睛主体。

## 待机运动为何更明显

代码中的默认正常态：

- 四角眼睑顺时针匀速旋转，15 秒一圈。
- 分层呼吸完整周期 1.44 秒，使用 cubic-bezier(.72,0,.28,1) 的来回运动。
- 眼白比例 .985↔.91，外虹膜 1↔.90，蓝环/高光层 1↔.87，瞳孔 1↔.85。
- 各层相位领先量为 0 / 45 / 90 / 180 ms，形成从内部向外传播的呼吸。
- 扩散环默认 4 秒周期，缩放 .98→2.78，同时快速减淡；不是整个圆盘闪烁。
- 还有随机故障撕裂、块移位和闪光。当前用户只要待机，不需要全部照搬这些干扰。

建议下一版优先采用：旋转四角 + 分层呼吸 + 白色软光晕。大范围脉冲应克制，
不带入 HDD 网格、面板、输入框、布局改造或语音。帧采样时必须处理不同周期的
接缝；不能把不闭合的 6 秒片段直接循环，也不宜盲目预生成极长公倍数周期。

## 本插件“看起来不动”的已有证据

新增 PTY 动态检查（不是单纯检查第一张图片）发现，正常空闲 1.2 秒发送：

- dark/regular：23 张不同 PNG
- dark/fullscreen：23 张不同 PNG
- light/regular：24 张不同 PNG
- light/fullscreen：23 张不同 PNG

因此独立 Pi 的发送端确实持续换帧。但不能据此证明用户 Warp 已正常合成每帧。
当前动画设计仅 6 秒周期、SVG 纵向位移 ±2.4/256、内环缩放 ±0.8%，显示缩小后
运动只有约几个像素。相比参考项目，动作过于微弱是有依据的解释，不是已排除
终端兼容问题后的最终诊断。下一次实机验证应同时观察明显的角度变化与帧发送。
